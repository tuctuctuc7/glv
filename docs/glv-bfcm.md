# GLV BFCM live promo report

Route `/glv-bfcm` uses the existing GLV beta login; `/api/glv-bfcm/data` independently validates the existing beta cookie or GLV server cron bearer credential. No new public data export or scheduled job is added.

The default light theme follows the supplied blue/blush glass reference: a white-rimmed gradient shell, separate frosted metric cards, pill controls and a pale high-contrast data table. The reference's decorative wellness graphics are not copied into the performance report. A top-right icon-only sun/moon button switches between light and the original dark theme. The route-local `glv-bfcm-theme` localStorage preference is applied before paint, with safe fallback when storage is unavailable. Theme changes do not fetch data or reset filters/sorting. The button has an accessible next-action label, keyboard support and a 44px target at every viewport size.

- Account `act_359758259164738`; verify CZK and Europe/Prague against Meta on each extraction.
- Default is an inclusive campaign-to-date range: `2026-11-25` through the current Europe/Prague day. From/To date inputs and Apply dates select a custom interval; Campaign to date restores the advancing default. Dates must be real ISO calendar dates, ordered, on/after campaign start and no later than Prague today, validated in UI and API. The API accepts paired `since`/`until` query parameters; omitting both resolves the default at extraction start.
- API contract `schema_version: glv-bfcm/v3`, `reporting_period: campaign-to-date | custom`, explicit inclusive `since`/`until`, `date` aliasing `until`, `timezone: Europe/Prague`, UTC `generated_at`, and `partial_day` true only when the end includes account today. Display the selected period, source refresh time and partial-day badge; historical selections are not labelled current-day partial.
- `Daily breakdown` is a native checkbox, OFF by default. `daily=1` requests one paginated ad-level Insights extraction with `time_increment=1`; `daily=0` (default) omits daily increments and uses full-range ad facts. Each page reuses the exact range and attribution options. Daily mode returns `daily_rows` grouped by campaign, concept and date; parent rows and totals sum those same daily absolutes, then derive ratios. Repeated ad IDs across different dates are expected and retained; duplicates within one date fail closed. `ad_count`/`source_ad_count` count contributing ad-day facts in daily mode, not unique ads. Separate full-range and daily source reads may differ due to Meta attribution/revisions; they are not represented as an atomic pair.
- Daily children remain chronological immediately under each parent in Concepts, Campaign + concept and Campaigns views. CC, PAC, AI EGC, Animated banners and Unmapped retain the same concept identity. Missing delivery days within an existing parent's interval render zero absolutes and null ratios; never synthesize impressions/purchases or invent inactive concepts. Independently inventoried zero-delivery campaigns remain visible in Campaigns view.
- Warm cache and in-flight requests are keyed by schema, both dates, daily mode and extraction-start Prague day (so historical-period partial metadata cannot leak across midnight). Cache lifetime remains 60 seconds, with at most 12 entries and 8 independent in-flight extractions per warm instance. Pagination is cursor-checked, deadline-bound and capped at 250,000 facts / 501 pages. Browser changes abort obsolete fetches and generation-guard both successful and failed responses. A different requested range/mode immediately clears the old results; failed/invalid changes cannot show old values under new labels. Same-scope refresh failure may retain explicitly stale values.
- Include only campaigns with a bounded `Promo-BFCM` token (spaces/underscores also accepted), irrespective of current delivery status. Exclude older Promo/Winners campaigns from both metrics and inventory. Inventory includes matching paused/archived/deleted campaigns; Insights adds any delivered BFCM Promo campaign not returned by inventory.
- Paginate ad-level Insights completely. CC/PAC and AI EGC concepts are extracted from the ad name first, then an unambiguous ad-set identifier only when no ad code exists. Thus ad-set CC13A/CC13B ads named CC13 belong to CC13. AI EGC plus the first number is the concept: Shared_AI-EGC_01_01 and Private_AI-EGC_01_04 both belong to AI EGC 01, regardless of ad-set audience labels or the second variant number. Uncoded/conflicting ads remain individually labelled Unmapped.
- Purchases and revenue use ordered action aliases (omni_purchase, purchase, pixel purchase), never summed aliases. Attribution follows the account setting with impression-time reporting.
- Explicit `AnimatedBanners` campaign labels override CC codes: all their ads aggregate into one `Animated banners` concept. Static banners retain their CC concepts; AI EGC and PAC grouping remain unchanged.
- Campaign selection is a checkbox multiselect, initially all BFCM campaigns selected. None means no campaigns, never All. Apply selection to every KPI/table/view and preserve it across refresh and view switches.
- ROAS = attributed purchase value/spend; CTR = all clicks/impressions; CPM = spend/impressions × 1000; Cost/LPV = spend/landing page views; CVR = purchases/landing page views. Percentages × 100; zero denominator is unavailable, not zero.
- Ratios are computed from summed absolutes. Default sort is purchases descending. Clicking any metric header first selects high-to-low; clicking it again selects low-to-high. Changing metric starts descending, including the first explicit click on the default Purchases header. Null ratios remain last in either direction. Sort is preserved across filters, views and refresh; a page reload restores the default. Default view aggregates concepts across campaigns; campaign+concept and campaign totals retain scope controls.
- Initial page load requests current Meta data. Manual Refresh does nothing (no request or UI change) unless the displayed snapshot is strictly more than 10 minutes old; exactly 10 minutes remains a no-op. With no successfully loaded snapshot, the button can retry immediately. The API's independent 60-second warm-instance cache is unchanged. Date Apply, Campaign to date and daily-toggle requests bypass the manual-button guard. The advancing default also refreshes at the next user request after Prague midnight. No automatic background polling, no changes to existing MAD cron/cache. Meta reporting lag remains and today is partial.
- No durable public snapshots, tokens, private local probes or evidence are part of the artifact.
